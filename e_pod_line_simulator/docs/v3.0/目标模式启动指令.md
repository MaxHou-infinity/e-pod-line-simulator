# V3.0 目标模式启动指令（可直接粘贴）

> 使用方式：把下方代码块整体复制到 Codex 对话中发送即可。全程无需人工参与。

```text
请创建目标（goal）并立即开始自主执行，全程不需要我参与，直到完成。

## 目标
完成电子烟产线仿真优化工具 V3.0 体验与视觉升级专项，按
`e_pod_line_simulator/docs/v3.0/体验视觉升级规划.md` 的 L1-L9 交付，
登记版本 v3.0.0 并打 tag `v3.0.0`。

## 必须先读的文件
- AGENTS.md（仓库贡献规范）
- e_pod_line_simulator/README.md
- e_pod_line_simulator/docs/v3.0/体验视觉升级规划.md（唯一规划依据）
- e_pod_line_simulator/docs/v3.0/开发日志.md 与 docs/v1.1/开发日志模板.md
- e_pod_line_simulator/docs/项目成熟度分析.md
- e_pod_line_simulator/logs.md

## 范围边界（不得越界）
- 必须完成（仅展示层与交互层）：
  - L1：Design Tokens 2.0（圆角/阴影/动效/双主题色板）
  - L2：亮/暗主题切换 + 持久化
  - L3：按钮/输入/卡片/对话框视觉规范落地
  - L4：KPI/报警/方案列表视觉升级
  - L5：画布视觉升级（网格、阴影、节点交互态）
  - L6：聚焦环、Tab 顺序、Esc/Enter 行为
  - L7：Toast 反馈、悬停/按下动效、报警栏折叠筛选
  - L8：命令面板（Ctrl+K，P2）
  - L9：全量回归、GUI 冒烟、文档同步、tag v3.0.0
- 明确不做：
  - 产品逻辑/功能开发（仿真、数据模型、业务 KPI、生产类型语义一律不变）
  - 破坏性变革（不迁 Web/Electron、不重写 GUI 框架）
  - 修改 PRD 原文
- 遇到模糊决策：按规划文档、AGENTS.md 和现有代码风格自行决定，
  并把决策写入开发日志；不要向我提问。
- 子 Agent 调度若不可用或未产出，由你（主控）直接完成对应角色分析并记录。

## 工作方式
- 按规划 L1→L9 顺序执行，一个 Loop 一次提交；每个 Loop 结束必须在
  `docs/v3.0/开发日志.md` 追加记录（含目标、验收、实际执行、验证结果、
  ✅/❌/⚠️ 判定、失败根因、文档同步、下一 Loop 输入）。
- 每次代码改动后运行：`python tests/test_basic.py` 与 `pytest`；
  若默认 Python 环境缺依赖，使用 Miniconda Python
  （/opt/homebrew/Caskroom/miniconda/base/bin/python3）并记录所用环境。
- 每完成一个 checkpoint 输出一条简短进度：当前 checkpoint、已验证内容、
  剩余工作、是否受阻；不等待我的回复。
- 文档与代码同步更新：README、项目成熟度分析、logs.md、开发日志。
- 提交信息遵循 Conventional Commits（feat:/fix:/docs:/test:/chore: + 简短中文描述）。

## 完成判定（全部满足才算完成）
1. 规划文档「八、验收标准」全部通过；
2. 亮/暗主题可切换并持久化，全部界面无对比度硬伤；
3. 2026 桌面美学特征落地（圆角/阴影/字阶/留白/微交互）；
4. 键盘可达：Tab/Enter/Esc 可完成核心流程；
5. 产品逻辑零变更：pytest 全绿，仿真结果与 V1.3 一致，
   核心模块覆盖率不下降（≥80%）；
6. GUI 冒烟通过（授权环境），Git 工作区干净，文档一致；
7. 版本号统一为 v3.0.0，已打 tag `v3.0.0`。

## 停止条件
- 上述完成判定全部满足 → 更新目标状态为 complete 并输出最终交付总结；
- 连续 3 个 Loop 因同一外部阻塞无法推进 → 更新目标状态为 blocked，
  说明阻塞原因和已完成的 Loop。

## 最终交付总结（完成后输出）
- Loop 清单（编号、结果、失败根因）
- 视觉/交互升级验收结果（含亮暗主题、组件、键盘可达、反馈）
- 测试与覆盖率数据
- tag 与提交记录
- 遗留问题清单
```
