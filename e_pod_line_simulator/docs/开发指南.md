# 开发指南

## 项目设计思路总结

### 一、架构设计（三层架构）

```
┌─────────────────────────────────┐
│     界面层（GUI）                │  ← 用户看到和操作的部分
│   - gui_main.py（主窗口）        │
│   - gui_canvas.py（画布）         │
│   - gui_panels.py（面板）         │
└─────────────────────────────────┘
           ↕ 数据传递
┌─────────────────────────────────┐
│     业务层（Simulation）         │  ← 核心计算逻辑
│   - simulation.py（仿真引擎）    │
│   - 瓶颈识别算法                  │
│   - 资源浪费检测                  │
└─────────────────────────────────┘
           ↕ 数据传递
┌─────────────────────────────────┐
│     数据层（Models）             │  ← 数据结构定义
│   - models.py（所有数据模型）    │
│   - Station（工序）               │
│   - ProductionLine（产线）        │
└─────────────────────────────────┘
```

### 二、核心文件说明

#### 1. models.py - 数据模型层

**作用**：定义所有数据结构

**主要类**：
- `Station`：工序模型，存储工序的所有信息
  - 基本信息：名称、ID、耗时
  - 资源配置：工人数、协作模式
  - 效率参数：OEE、人员效率
  - 计算方法：`get_capacity()`计算产能

- `ProductionLine`：产线模型，管理多个工序
  - 工序管理：添加、删除、查找
  - 产线分析：找出瓶颈、计算KPI
  - KPI计算：日产量、成本、平衡率

**关键方法**：
```python
station.get_capacity()  # 计算工序产能
line.find_bottleneck()  # 找出瓶颈工序
line.calculate_daily_output()  # 计算日产量
```

#### 2. simulation.py - 仿真引擎层

**作用**：运行产线仿真

**核心类**：
- `SimulationEngine`：仿真引擎
  - 初始化SimPy环境
  - 启动工序进程
  - 监控瓶颈和WIP
  - 收集仿真结果

**关键流程**：
1. 创建SimPy环境
2. 初始化资源（工人、缓冲区）
3. 启动工序进程（每个工序一个进程）
4. 启动监控进程（瓶颈、WIP）
5. 运行仿真直到指定时间

**SimPy核心概念**：
- `Environment`：仿真环境，管理时钟
- `Resource`：资源（工人），可以被竞争使用
- `Store`：存储（缓冲区），用于物料传递
- `Process`：进程，用生成器函数实现（yield）

#### 3. scenario_manager.py - 方案管理模块

**作用**：保存、删除和对比产线配置方案

**主要类**：
- `Scenario`：方案数据模型，保存产线配置快照（深拷贝），可实时计算 7 项 KPI
- `ScenarioManager`：方案管理器，最多保存 3 个方案，提供对比与推荐逻辑

#### 3. gui_main.py - 主窗口

**作用**：管理整个GUI界面

**主要功能**：
- 创建和布局所有GUI组件
- 处理菜单栏事件（文件、编辑、仿真等）
- 管理产线数据
- 控制仿真流程

**关键方法**：
```python
app.run()  # 启动GUI主循环
_update_display()  # 更新所有显示
_btn_start_simulation()  # 开始仿真
```

#### 4. utils.py - 工具函数

**作用**：提供通用功能

**主要功能**：
- 文件I/O：`load_config()`, `save_config()`
- 参数校验：`validate_station()`, `validate_production_line()`
- 日志管理：`setup_logger()`
- 辅助函数：`format_time()`, `get_status_color()`

### 三、数据流向

```
用户操作（点击按钮）
  ↓
GUI接收事件（gui_main.py）
  ↓
创建/更新Models（models.py）
  ↓
调用Simulation（simulation.py）
  ↓
SimPy运行仿真
  ↓
返回结果（SimulationState）
  ↓
GUI更新显示（gui_canvas.py, gui_panels.py）
```

### 四、开发顺序建议（新手友好）

#### Phase 1: 数据模型（第1周）
**目标**：能创建和操作工序对象

```python
# 测试代码
from models import Station, ProductionLine, CollaborationType

# 创建工序
station = Station("s01", "注油", 25, 2)
print(station.get_capacity())  # 查看产能

# 创建产线
line = ProductionLine("测试产线")
line.add_station(station)

# 找出瓶颈
bottleneck = line.find_bottleneck()
print(f"瓶颈：{bottleneck.name}")
```

#### Phase 2: GUI基础（第2周）
**目标**：能显示工序列表

```python
# 测试GUI
import tkinter as tk
from gui_main import MainWindow

app = MainWindow()
app.run()
```

#### Phase 3: 仿真引擎（第3周）
**目标**：能运行仿真

```python
# 测试仿真
from simulation import SimulationEngine

engine = SimulationEngine(line)
engine.run(duration_hours=8, speed=16)
results = engine.get_results()
```

#### Phase 4: 完善功能（第4周）
**目标**：画布显示、KPI仪表盘

### 六、常见问题

#### Q1: 如何添加新功能？

**步骤**：
1. 数据模型：在`models.py`中添加新类或字段
2. 业务逻辑：在`simulation.py`中添加计算逻辑
3. GUI界面：在`gui_*.py`中添加界面组件

**示例**：添加新KPI指标
```python
# 1. 在ProductionLine中添加计算方法
def calculate_new_kpi(self) -> float:
    # 计算逻辑
    return value

# 2. 在KPIDashboard中添加显示
def update_kpis(self, kpis):
    if 'new_kpi' in kpis:
        self.kpi_labels['new_kpi'].config(text=f"{kpis['new_kpi']:.2f}")
```

#### Q2: 如何调试代码？

**方法1**：使用print语句
```python
print(f"当前状态：{state}")
```

**方法2**：使用日志
```python
from utils import setup_logger
logger = setup_logger()
logger.info("调试信息")
```

**方法3**：使用断点调试（IDE）
- PyCharm：点击行号左侧设置断点
- VSCode：按F9设置断点

#### Q3: 代码运行出错怎么办？

**步骤**：
1. 查看错误信息（通常最后一行是错误原因）
2. 检查导入是否正确
3. 检查数据类型是否正确
4. 检查参数是否合法

**常见错误**：
- `ImportError`：导入错误，检查模块路径
- `AttributeError`：属性错误，检查对象是否有该属性
- `TypeError`：类型错误，检查参数类型

### 七、代码规范

#### 1. 命名规范
- 类名：首字母大写，如`Station`, `ProductionLine`
- 函数名：小写+下划线，如`get_capacity()`, `find_bottleneck()`
- 变量名：小写+下划线，如`station_id`, `total_output`

#### 2. 注释规范
- 每个类都有文档字符串（docstring）
- 每个函数都有文档字符串
- 关键逻辑有行内注释

#### 3. 代码组织
- 一个文件一个主要功能
- 相关功能放在一起
- 避免过长的函数（超过50行考虑拆分）
