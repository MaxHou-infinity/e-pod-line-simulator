# V1.3 目标模式启动指令（可直接粘贴）

```text
请创建目标（goal）并立即开始自主执行，全程不需要我参与，直到完成。

## 目标
完成电子烟产线仿真优化工具 V1.3（v1.3.0）产品形态扩展：烟油与尼古丁袋，
按 `e_pod_line_simulator/docs/v1.3/需求与开发路线图.md` 的 P0/P1 范围交付，
并打 tag `v1.3.0`。

## 必须先读的文件
- AGENTS.md（仓库贡献规范）
- e_pod_line_simulator/README.md
- e_pod_line_simulator/docs/v1.3/需求与开发路线图.md（唯一规划依据）
- e_pod_line_simulator/docs/v1.3/开发日志.md 与 docs/v1.1/开发日志模板.md
- e_pod_line_simulator/docs/项目成熟度分析.md
- e_pod_line_simulator/logs.md

## 范围边界（不得越界）
- 必须完成：
  - P0：生产类型模板（assembly / liquid_filling / pouch_packaging）、
    Recipe/Batch/Tank 模型、批量过程仿真、CIP/SIP 清洗切换、
    机台节拍、人力模型（工种/技能矩阵/洁净区上限）、
    质量门（在线检测/批次放行）
  - P1：KPI 扩展、报告导出扩展、Excel/JSON 数据扩展、
    向导生产类型选择
  - P2（仅 M4 收尾内）：流程型布局、批次甘特图、清洗状态高亮
- 明确不做：
  - 合规约束建模（BPOM/SNI/GMP/RPTKA 等不影响产线排程，
    按用户决策不纳入仿真模型，不得在排程/仿真中实现）
  - Web 化（V2.0）、AI 优化（V1.4）、多产线协同、3D、移动端、HNB 整机
  - 不修改 PRD 原文；保持 V1.0/V1.1/V1.2 已有功能不回归
- 遇到模糊决策：按路线图、AGENTS.md 和现有代码风格自行决定，
  并把决策写入开发日志；不要向我提问。
- 子 Agent 调度若不可用或未产出，由你（主控）直接完成对应角色分析并记录。

## 工作方式
- 按路线图 L0→L8 顺序执行，一个 Loop 一次提交；每个 Loop 结束必须在
  `docs/v1.3/开发日志.md` 追加记录（含目标、验收、实际执行、验证结果、
  ✅/❌/⚠️ 判定、失败根因、文档同步、下一 Loop 输入）。
- 每次代码改动后运行：`python tests/test_basic.py` 与 `pytest`；
  若默认 Python 环境缺依赖，使用 Miniconda Python
  （/opt/homebrew/Caskroom/miniconda/base/bin/python3）并记录所用环境。
- 每完成一个 checkpoint 输出一条简短进度：当前 checkpoint、已验证内容、
  剩余工作、是否受阻；不等待我的回复。
- 文档与代码同步更新：README、项目成熟度分析、logs.md、开发日志。
- 提交信息遵循 Conventional Commits（feat:/fix:/docs:/test:/chore: + 简短中文描述）。

## 完成判定（全部满足才算完成）
1. 路线图「四、验收标准」全部通过：P0 必须满足，P1 按规划完成；
2. 烟油单批次仿真结果与手工计算误差 < 3%；尼古丁袋节拍模型符合
   节拍 × 工位逻辑；
3. pytest 全绿；核心模块覆盖率 ≥80%（至少实测并记录数值）；
4. V1.0/V1.1/V1.2 回归全部通过：启动、工序增删改、JSON 保存/加载、
   Excel 导入、仿真启停/暂停、方案对比、报告导出、GUI 交互；
5. GUI 冒烟验证：有显示环境则实际启动（需授权），无显示环境则记录
   headless 验证结果；
6. Git 工作区干净，文档与代码一致；
7. 已打 tag `v1.3.0`。

## 停止条件
- 上述完成判定全部满足 → 更新目标状态为 complete 并输出最终交付总结；
- 连续 3 个 Loop 因同一外部阻塞无法推进 → 更新目标状态为 blocked，
  说明阻塞原因和已完成的 Loop。

## 最终交付总结（完成后输出）
- Loop 清单（编号、结果、失败根因）
- 各 P0/P1 功能的验收结果（含烟油/尼古丁袋专项验证数据）
- 测试与覆盖率数据
- tag 与提交记录
- 遗留问题清单
```
