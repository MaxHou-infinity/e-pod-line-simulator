# V3.3 分析体验与学习成本优化：需求与开发路线图（正式版）

> 版本：v3.3.0 立项文档
> 制定日期：2026-08-11
> 基线：v3.2.0（tag `v3.2.0`）
> 立项方式：主控 Agent 对「分析」菜单全功能呈现与学习成本诊断 +
> 用户实测反馈（智能优化结果可读性）

## 一、背景与目标

V3.2 之后，「分析」菜单已有 8 个功能：方案对比、方案管理、敏感性试算、
人力规划、KPI 历史趋势、批量试算、智能优化、导出报告。功能数量增加后，
存在三类体验问题：

1. **呈现形式不统一**：部分功能用表格对话框（方案对比/批量试算），
   部分用纯文本弹窗（敏感性试算/智能优化），人力规划用文本区，
   用户需要重新学习每个功能的阅读方式；
2. **学习成本偏高**：几乎所有对话框都没有“这个功能解决什么问题、
   每个输入是什么意思、结果怎么读”的解释；专业术语（UPPH、OEE、
   缺勤率、爬坡、失衡分析等）缺少就地说明；
3. **决策信息不完整**：智能优化输出原始 Python 字典、无基线对比、
   无单位成本口径说明；敏感性试算不可导出；长时间任务无进度反馈。

V3.3 目标：**统一分析结果的呈现与操作方式，让每个功能“打开即懂、
看完能决策、结果能带走”**，并把用户已确认的智能优化增强纳入本次迭代。

## 二、现状诊断（按「分析」菜单逐项）

| 功能 | 当前呈现 | 学习成本问题 |
|------|----------|--------------|
| 方案对比 | Treeview 表格 | 较好；缺列名解释与“推荐依据”说明 |
| 方案管理 | Treeview 表格 | 较好；缺批量删除/导入导出说明 |
| 敏感性试算 | messagebox 纯文本 | 高：不可对比排序、不可导出、无口径说明 |
| 人力规划 | 表单 + Text 结果 | 中：结果非表格，术语无解释，参数含义不直观 |
| KPI 历史趋势 | Treeview + Canvas 折线 | 较好；缺导出/清空/多 KPI 对比 |
| 批量试算 | 表单 + Treeview | 中：参数无解释，结果无基线标记与图表 |
| 智能优化 | 表单 + messagebox 原始 dict | 高：结果难读，无基线对比、无进度、无口径说明 |
| 导出报告 | 文件对话框 | 低；缺导出内容（Sheet 清单）预览说明 |

## 三、设计原则

1. **呈现统一**：所有分析结果一律表格化（Treeview），支持导出；
2. **解释先行**：每个对话框提供「使用说明」折叠区或帮助按钮，
   说明目的、输入含义、输出口径、适用场景，并链接术语表；
3. **决策可对比**：凡有“基线”的功能，结果均标注 Δ 并与基线高亮；
4. **过程有反馈**：超过约 2 秒的计算任务显示进度（状态栏/进度条）；
5. **结果可带走**：分析结果支持导出 Excel/复制到剪贴板。

## 四、需求规格

### P0 - 本次必达

**P0.1 分析结果统一表格组件**
- 新增通用“结果表格对话框”：列定义、基线行高亮、Δ 列、导出 Excel、
  复制文本；
- 敏感性试算、智能优化、人力规划结果迁移到该组件。

**P0.2 智能优化体验重构（用户已确认）**
- 结果表格化：排名/目标值/总产出/单位成本/UPPH/总人数/各工序参数；
- 增加“较基线 Δ”（产出、单位成本、人数）；
- 增加“实际单位成本 = 总成本 ÷ 仿真总产出”口径列，并与理论口径并列；
- 初始种群注入当前产线配置（保证结果不差于现状）；
- 工序锁定开关：固定人数/缓冲区/节拍，不参与搜索；
- 进度反馈：优化期间状态栏显示“第 X/Y 代”，完成后 Toast；
- 结果展示前先格式化参数（工序名、人数、缓冲区、节拍）。

**P0.3 敏感性试算升级**
- 从 messagebox 改为表格对话框：基线高亮、Δ 排序、导出 Excel；
- 增加口径说明：产出为仿真值，单位成本为理论口径（并展示实际口径）；
- 增加“尝试全部建议方案”按钮：把 TOP 建议一键应用到产线。

**P0.4 每个分析功能内置「使用说明」**
- 敏感性试算、人力规划、批量试算、智能优化、KPI 历史趋势、
  方案对比各增加折叠式说明区（目的/输入/输出/口径/示例）；
- 术语字段旁提供 Tooltip（复用现有 ToolTip 组件），
  如 UPPH、OEE、缺勤率、离职率、爬坡天数、失衡分析、实际利用率。

### P1 - 本次增强

- **P1.1 人力规划结果表格化**：工种人数、成本、招聘缺口改为表格，
  关键术语就地解释；增加“按当前产线填充”快捷按钮；
- **P1.2 批量试算可视化**：参数解释、基线行标记、折线图对比
  （复用 HistoryDialog 画布思路）；
- **P1.3 KPI 历史趋势增强**：导出/清空历史、多 KPI 同图对比、
  参考线（当前值）；
- **P1.4 「分析指南」帮助页**：菜单增加“分析指南...”，
  用表格说明“何时用哪个功能/操作步骤/典型问题”。

### P2 - 后续候选

- 最近分析记录（跨会话记住上次参数与结果）；
- 向导式分析入口（选择目标 → 推荐功能）；
- 分析结果统一 PDF 汇总。

## 五、里程碑与 Loop 计划

- **M1（基础组件）**：通用结果表格组件 + 使用说明组件 + 版本登记 v3.3.0；
- **M2（功能升级）**：智能优化重构、敏感性试算升级、进度反馈；
- **M3（体验增强）**：人力规划表格化、批量试算图表、KPI 历史增强、
  分析指南、全量验收。

每个 Loop 沿用 `docs/v1.1/开发日志模板.md`，记录目标、验收标准、
实际执行、验证结果、成功/失败根因、文档同步与遗留事项。

## 六、验收标准（P0 必达）

1. 「分析」菜单所有功能结果均为表格化呈现，可导出；
2. 每个分析对话框均有「使用说明」，专业术语有就地解释；
3. 智能优化：结果含基线 Δ、实际单位成本、参数格式化；
   初始种群含当前配置；锁定开关生效；有进度反馈；
4. 敏感性试算：基线高亮、Δ 排序、导出可用；
5. 全量 pytest 全绿（126 + 新增用例）；GUI 冒烟通过；
6. 版本号 v3.3.0 + tag + 文档/日志同步。

## 七、范围边界与风险

- **不做**：仿真引擎语义变更、生产类型模型变更、Web 化；
- 智能优化增强中的“实际单位成本”为新口径列，不修改既有
  `unit_cost` 语义，避免破坏历史报告；
- 风险：分析功能较多，需保证各功能回归不受影响；
  每个 Loop 独立提交并跑全量测试。
