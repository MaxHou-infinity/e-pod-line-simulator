# V1.2.0 交互与视觉专项开发路线图

> 版本：v1.2.0 规划文档
> 制定日期：2026-08-07
> 基线：V1.1.0（tag `v1.1.0`，功能已验收）

## 一、版本定位与范围

**版本定义**：V1.2.0 是交互体验与视觉体验专项提升版。功能能力保持 V1.1 不变，
聚焦"看得更清楚、操作更顺手、反馈更及时"。

**版本范围变更记录**：原 V1.1 路线图将 V1.2 定义为"AI 自动优化"；经本次决策，
V1.2.0 调整为交互/视觉专项，AI 优化顺延至 V1.3。

**明确排除**：AI 自动优化（V1.3）、Web 化（V2.0）、多产线/3D/移动端。

## 二、多 Agent 调度说明

按要求调度「美学 Agent / 前端设计 Agent / 交互设计 Agent」各一次：
三个子 Agent 均反馈未收到任务描述（平台消息投递不可用）。
由主控 Agent 代行三角色诊断，结论如下，诊断过程已如实记录。

## 三、视觉诊断（美学视角）

### 3.1 现状问题

| # | 问题 | 位置 |
|---|------|------|
| V1 | 无统一设计令牌：颜色/字体/间距散落硬编码 | gui_main/gui_panels/gui_canvas |
| V2 | 状态色过饱和：纯绿/纯红/纯黄直接填充节点 | utils.get_status_color |
| V3 | 画布节点为直角矩形 + 全填充，无状态条/徽标/阴影层级 | gui_canvas._draw_station |
| V4 | KPI 仅纯文字标签，无卡片化与视觉层级 | gui_panels.KPIDashboard |
| V5 | 字体固定 Arial，未适配 PingFang SC/微软雅黑，中文观感一般 | 全部 GUI |
| V6 | 报警面板纯文本堆叠，无图标/级别色条 | gui_panels.AlertPanel |
| V7 | 对话框/按钮使用系统默认样式，与画布风格割裂 | 各 Dialog |
| V8 | 无空状态设计：空白产线画布没有任何引导 | gui_canvas.update_production_line |

### 3.2 视觉提升方向

- **设计令牌**：新增 `src/theme.py`，统一中性色、主色、强调色、状态色、
  字体与间距（4/8/12/16/24）。
- **状态色体系**：运行 `#34C759`、堵塞 `#FF3B30`、等待 `#FF9F0A`、
  切换 `#0A84FF`、空闲 `#E5E5EA`；节点改为"浅色填充 + 顶部状态条 + 边框"。
- **画布节点**：圆角卡片、状态条、瓶颈徽标、选中描边、拖拽跟随。
- **KPI 仪表盘**：卡片化单元格（数值 + 单位 + 趋势位），弱化纯蓝/纯绿。
- **报警面板**：级别色条 + 图标（⚠️/🔴/ℹ️）+ 结构化文本。
- **字体**：优先 PingFang SC（macOS）/ 微软雅黑（Windows），回退 Arial。

## 四、实现方案（前端设计视角）

### 4.1 技术路径

- 保持 Tkinter；用 `ttk.Style` + 自绘 Canvas 实现视觉升级，不引入新框架。
- 新增 `src/theme.py`：设计令牌、字体解析、`apply_theme(root)`。
- Canvas 自绘圆角矩形（多边形平滑）与状态条；图标继续使用 emoji + 几何图形。
- HiDPI：按系统缩放设置 `tk scaling`，保证高分屏清晰。

### 4.2 改动文件与工作量

| 阶段 | 文件 | 内容 | 工作量 |
|------|------|------|--------|
| M1 | theme.py（新增）、utils.py、gui_main.py | 令牌、主题、字体、空状态 | 1 天 |
| M2 | gui_canvas.py | 节点卡片、状态条、拖拽落点提示 | 1-2 天 |
| M3 | gui_panels.py | KPI 卡片、报警样式、对话框统一 | 1-2 天 |
| M4 | 全部 + tests | 打磨、HiDPI、回归 | 1 天 |

## 六、开发路线图（Phase / Loop）

### M1：设计基础（Loop U1-U2）

- U1：`theme.py` 设计令牌 + `apply_theme` + 字体适配
- U2：空状态提示 + 状态徽标 + 状态色体系切换

### M2：画布视觉与交互（Loop U3-U4）

- U3：节点卡片化（圆角/状态条/瓶颈徽标/选中描边）
- U4：拖拽落点提示 + 运行中交互禁用 + 光标反馈

### M3：面板、对话框与全局交互（Loop U5-U6）

- U5：KPI 卡片化 + 报警面板视觉重构
- U6：快捷键 + 脏状态确认 + 导出进度 + 错误提示优化

### M4：打磨与发布（Loop U7）

- U7：对话框统一、Tooltip、HiDPI、全量回归、GUI 冒烟、
  文档同步、打 tag `v1.2.0`

## 七、验收标准

1. pytest 全绿；核心模块覆盖率不因本次改动下降（≥80%）
2. GUI 冒烟通过（授权环境）
3. 视觉评审：状态色/字体/卡片/报警/KPI 符合设计令牌规范
4. 交互验收：用户可在无引导提示下完成
   新建→配置→仿真→方案对比→导出 五个核心任务
5. 空状态、运行状态徽标、快捷键、脏状态确认、导出进度全部生效
6. 版本号统一为 v1.2.0，README/成熟度分析/开发日志同步

## 八、风险

| 风险 | 应对 |
|------|------|
| Tkinter 主题跨平台差异 | 设计令牌集中管理，macOS/Windows 分别冒烟 |
| 视觉改动影响功能回归 | 每个 Loop 跑 pytest + GUI 冒烟 |
| 范围蔓延（AI/Web） | 严格执行排除项 |
