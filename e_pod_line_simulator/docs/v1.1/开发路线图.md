# 电子烟产线仿真优化工具 V1.1 开发路线图

> 版本：v1.1.0 规划文档
> 制定日期：2026-08-07
> 基线：V1.0（commit `8deaef1` 之前的状态，MVP 已基本完成）

## 一、V1.1 目标与定位

**一句话定义**：V1.1 是"易用性与完整性增强版"——补齐 V1.0 遗留的 PRD 核心缺口，
并完成版本号、日志、测试等工程化基础，为 V1.2（AI 优化）与 V2.0（Web 化）打底。

边界：
- 包含：报告导出、切换事件、拖拽排序、方案对比扩展、画布交互、快速配置向导、工程化。
- 明确排除：AI 自动优化（V1.2）、Web 化（V2.0）、多产线协同、3D 可视化、移动端。

## 三、代码实现方式（后端视角）

### 3.1 保持现有架构，做最小必要调整

继续保留 V1.0 的 7 文件三层结构（Models / Simulation / GUI / Utils），新增少量模块：

```
src/
├── version.py        # 新增：__version__ 统一版本入口
├── reporting.py      # 新增：仿真结果聚合与 Excel/PDF 导出
├── simulation.py     # 改造：事件注入 + headless 运行模式
├── scenario_manager.py # 改造：方案上限 3 → 5
└── gui_*.py          # 改造：交互与向导
```

### 3.2 切换事件实现方案

1. `SimulationEngine` 增加线程安全事件队列 `event_queue`；
2. 新增 `trigger_changeover(station_id, minutes=45)` 方法；
3. 工序进程在加工循环中检查事件：命中后进入 `changeover` 状态并 `timeout(minutes*60)`；
4. 切换期间上下游按 WIP 机制自然堵塞/等待，报警面板可显示切换事件；
5. GUI 通过右键菜单或"仿真 → 触发切换"调用。

### 3.3 报告导出实现方案

1. 新增 `SimulationResult` 聚合对象：KPI、各工序产出、WIP 采样、报警列表、配置快照；
2. `reporting.py` 提供 `export_excel(result, path)` 与 `export_pdf(result, path)`；
3. Excel 用 `openpyxl/pandas`，PDF 用 `reportlab`（新增依赖）；
4. GUI 的"导出报告"菜单从占位提示改为文件保存对话框。

### 3.4 可测试性改造

- 仿真引擎支持 headless 模式：`run(duration_hours, speed, headless=True)` 直接返回
  `SimulationResult`，不依赖 GUI 线程，供 pytest 快速验证；
- 状态回调统一改为队列传递到 GUI 线程，消除跨线程直接调用 GUI 的隐患。

## 四、前端交互方向（前端视角）

### 4.1 技术方向

V1.1 继续使用 Tkinter，不引入 Web 技术栈。V2.0 再按
`docs/Web化方案分析.md` 的纯前端方案立项，避免 V1.1 范围失控。

### 4.2 画布交互

- 拖拽排序：`<B1-Motion>` 拖动节点，松手后调用 `ProductionLine` 重新排序并重绘；
- 双击编辑：现有 `_on_double_click` stub 增加回调，打开 `StationDialog`；
- 右键菜单：`<Button-3>` 弹出菜单（编辑/删除/触发切换）；
- 选中状态：单击节点高亮，配置面板同步选中。

### 4.3 快速配置向导

- 新增 `WizardDialog`：步骤 1 模板选择 → 步骤 2 数据来源（手动/Excel）→
  步骤 3 班次设置 → 步骤 4 自动运行首次仿真并展示结果；
- 可跳过，向导入口放在"文件"菜单与首次启动提示。

## 五、测试与质量策略（测试视角）

### 5.1 测试框架与覆盖

- 框架：pytest（保留 `tests/test_basic.py` 兼容入口）；
- 新增：`tests/test_models.py`、`tests/test_simulation.py`、
  `tests/test_scenario.py`、`tests/test_reporting.py`；
- 目标：核心模块（models/simulation/scenario_manager/reporting）行覆盖率 ≥80%。

### 5.2 回归矩阵

| 范围 | 必测项 |
|------|--------|
| V1.0 回归 | 启动、工序增删改、JSON 保存/加载、Excel 导入、仿真启停/暂停、方案对比、KPI 计算 |
| V1.1 新增 | 切换事件、拖拽排序、双击/右键、导出文件内容、向导流程、方案 5 个上限 |

每个 Loop 结束必须：`pytest` 全绿 + 基础测试通过 + 文档同步 + Git 提交。

## 六、实施顺序与 Loop 划分

### M1：工程化基础 + 引擎能力（建议 1-1.5 周）

- L0：版本号常量、日志完善、pytest 骨架、Git 分支规范
- L1：切换事件（引擎 + GUI 触发）
- L2：仿真结果聚合与报告导出

### M2：前端交互与向导（建议 1-1.5 周）

- L3：拖拽排序
- L4：双击/右键/选中交互
- L5：快速配置向导

### M3：收尾与发布（建议 1 周）

- L6：方案数量扩展至 5 + 方案持久化
- L7：KPI 历史与趋势（P2）
- L8：全量回归、文档同步、打 `v1.1.0` tag

## 七、开发 Loop 记录规范

每个 Loop 使用 `docs/v1.1/开发日志模板.md` 记录，文件按
`docs/v1.1/开发日志.md` 追加，字段：

1. Loop 编号、日期、负责角色
2. 目标与验收标准
3. 计划改动（文件 + 功能）
4. 实际执行内容
5. 验证结果（命令与输出摘要）
6. 结果判定：✅ 成功 / ❌ 失败 / ⚠️ 部分成功
7. 失败根因与调整决策
8. 文档同步状态
9. 下一 Loop 输入

**成功判定**：验收标准全部满足 + 测试全绿 + 文档同步 + 已提交。
